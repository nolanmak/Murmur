## Outcome

Dictate into the local Mac microphone, review the final transcript, then choose **Paste to remote computer** to insert it into the intended RustDesk session. Remote targets are macOS and Linux desktops, including terminal inputs. No dictation app, audio forwarding, provider credential, or new service is required on the remote computer.

This is a scoped implementation issue, not a claim that RustDesk integration already works. Local browser insertion is still being validated separately.

## Scope and dependencies

- Reuse local microphone capture and final transcription from #3 and #4; preserve cancellation from #2.
- Extend insertion routing from #6 with a separate remote destination. Reuse status/error UI from #7.
- Stable local app signing and permission behavior from #11 are prerequisites for reliable release validation.
- This does not require the Linux dictation port in #12. A headless Linux server without a RustDesk graphical session is outside this feature; dictating into a local terminal running SSH remains the local terminal use case.
- MVP is explicit, review-then-paste. Automatic paste on Control release is a later, gated phase.
- Preliminary estimate: 1–3 development days for a prototype after the transport feasibility check. Release hardening and the cross-platform matrix require separate estimation from that evidence.

- [ ] Demonstrate local-to-remote plain-text clipboard transfer and remote paste on one macOS and one Linux desktop using a harmless fixture. Inspect the remote field contents; a successful local API call is not proof of insertion.
- [ ] Establish whether the active session, reconnects, clipboard availability, and remote receipt can be detected reliably. Document what is observable and what is not.

If reliable synchronization cannot be observed, ship explicit copy/manual remote paste as the fallback rather than use an arbitrary delay and report success.

## MVP acceptance criteria

### User flow

- [ ] Remote mode is opt-in. Normal local dictation continues to work when remote mode is off.
- [ ] Audio is captured on the local Mac and transcribed locally through the configured provider connection; only the final reviewed text is shared through RustDesk.
- [ ] After transcription, show the final text and the selected remote destination. Sharing/pasting begins only when the user chooses **Paste to remote computer**.
- [ ] The action requires an active, identified RustDesk session. An unrelated foreground app, an ambiguous session, or unavailable transport blocks the action with a useful explanation and retains the transcript for retry.
- [ ] The user chooses a paste profile explicitly: macOS `Command+V`, Linux standard input `Ctrl+V`, or Linux terminal `Ctrl+Shift+V`. A custom shortcut may be added only if needed by the measured target matrix. Do not infer terminal mode solely from the remote OS.
- [ ] Releasing the local hotkey is not forwarded as a remote command. Pasting never sends Enter, Return, or an automatic submit/execute action.
- [ ] Status distinguishes preparing, waiting for clipboard transfer, paste requested, failed, and cancelled. Say **Inserted** only when supported evidence verifies remote insertion; otherwise say **Paste sent—check remote input**.

### Destination and failure handling

- [ ] Capture a destination/session token and generation for each attempt. Revalidate immediately before sharing and before dispatching paste. Session switch, disconnect, reconnect, focus drift to another local window, or cancellation invalidates pending work.
- [ ] Do not claim to detect the focused remote widget or remote password fields unless the selected integration actually exposes that information. If remote focus cannot be verified, require the user to focus the intended field and confirm the explicit paste action. No unattended automatic mode under that limitation.
- [ ] Delayed or reordered completion cannot paste an older transcript. Repeated callbacks or double clicks dispatch at most one paste per attempt. Retry creates a new explicit attempt; never silently retry after an uncertain dispatch.
- [ ] Clipboard synchronization and paste dispatch have bounded, configurable deadlines and cancellation checks. Test below, at, and beyond each deadline; timeout keeps the transcript available and does not dispatch late work.
- [ ] Disabled clipboard sharing, missing keyboard permission, locked/disconnected sessions, and unsupported hosts produce distinct actionable errors. No remote permission or security setting is changed silently.

### Clipboard and text integrity

- [ ] Preserve Unicode, punctuation, and ordinary whitespace end to end. Do not interpret transcript text as shell commands, scripts, URLs, or shortcut sequences.
- [ ] For the MVP, reject embedded control characters and multiline transcripts in remote mode with a clear explanation. Do not claim clipboard paste alone prevents command execution in all terminals; no automatic execution is permitted.
- [ ] Snapshot supported local clipboard formats before replacing them. Do not destroy unsupported/multiple-item clipboards; offer manual copy instead when lossless restoration is unavailable.
- [ ] Restore the local clipboard only when transfer/consumption is confirmed and the clipboard still belongs to this attempt. Never overwrite a newer clipboard change. If consumption cannot be confirmed, explain that the transcript remains copied and offer explicit restoration; do not restore on a blind fixed timer.
- [ ] Explain that RustDesk clipboard sync can change the remote clipboard; do not promise restoration of the remote clipboard without transport support.
- [ ] Do not log or persist transcript contents, clipboard contents, credentials, session secrets, remote addresses, or remote machine names. Diagnostics use non-sensitive state/error codes. CI uses synthetic text and no live provider or RustDesk secrets.

## Architecture boundaries

- Pure controller: destination selection, generations, cancellation, deadlines, one-dispatch-per-attempt, and retry policy.
- Injectable `RemoteSession`, `ClipboardTransport`, `PasteDispatcher`, and monotonic clock interfaces. Native callbacks enqueue events; they do not perform blocking I/O or decide lifecycle transitions.
- Keep remote transport separate from local AX insertion and provider code. Do not broaden local secure-field checks or treat a RustDesk canvas as an ordinary editable field.
- Clipboard ownership/restoration is attempt-scoped. Cleanup is idempotent on success, failure, cancellation, and shutdown.

## Test-first implementation plan

For each behavior below: commit a failing behavioral test (red), implement the smallest production change that passes (green), then refactor with the suite green. A renamed test, compilation success, or mocked API success alone is not native integration evidence.

1. **Controller:** fake session/clock/transport tests for explicit opt-in, target mismatch, multiple sessions, focus drift, disconnect/reconnect, cancellation at every stage, stale generations, double-clicks, and retry after uncertain dispatch.
2. **Clipboard:** delayed delivery, missing acknowledgement, deadline boundaries, synchronization disabled, non-text/multiple-item clipboard, external clipboard changes, and restoration ownership. Assert actual payload and lifecycle—not implementation-specific call order alone.
3. **Paste policy:** parameterized macOS/Linux/terminal profiles; Unicode fixtures; rejection of multiline/control characters; assert that no Enter/Return event is generated and paste dispatch occurs at most once.
4. **Adapter contract:** run the same behavior contract against the fake adapter and the real integration where observable. Include delayed transport and disconnect chaos cases. An unavailable real environment is an explicit skip, never a pass.
5. **Native end-to-end:** with disposable, harmless test fields, dictate or feed an explicitly labeled fixture through the app, invoke the remote action, and verify the remote field's final contents. Do not substitute typing/pasting directly with the test runner for the application's insertion path.

## Required native validation matrix

| Local controller | Remote host | Target | Required evidence |
| --- | --- | --- | --- |
| macOS | macOS | Notes/text editor | Exact expected text, original surrounding text retained |
| macOS | macOS | Chrome input, textarea, contenteditable | Text visible in each field; no form submitted |
| macOS | macOS | Terminal | Text inserted at prompt; nothing executed |
| macOS | Linux/X11 | Browser input and terminal | Correct paste profile and exact field contents |
| macOS | Linux/Wayland | Browser input and terminal | Pass on supported RustDesk configuration or documented unsupported limitation with graceful blocking |
| macOS | macOS and Linux | Slow sync, disabled sync, focus/session change, disconnect | No wrong-target/duplicate/late paste; transcript recoverable |

Record OS, desktop/session type, RustDesk versions, paste profile, observed result, and sanitized evidence for each row. Do not include account identities, addresses, real conversations, or remote connection IDs in public issue attachments.

## Later phase: automatic paste on release

- Separate explicit opt-in setting, disabled by default.
- Only pursue after MVP evidence establishes reliable destination validation and synchronization. If remote focus/receipt remains unobservable, retain explicit review and paste rather than imply guarantees the transport cannot provide.
- Reuse the same cancellation, session, clipboard, and timeout contract; extend the matrix before enabling it in a release.
