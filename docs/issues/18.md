## Outcome
Implement a global X11 shortcut adapter using shared hold semantics.

## Acceptance criteria
- [ ] Left/right Control and their overlap trigger one recording after the existing hold threshold; release stops once.
- [ ] Quick taps and normal Control chords retain their behavior; Escape cancels without insertion.
- [ ] Lost focus/session, key-up loss and shutdown cannot leave recording stuck; recovery is deterministic.
- [ ] Manual start/stop remains available when a shortcut conflicts or cannot register; failure is shown.
- [ ] Native X11 evidence covers terminal, editor and browser while macOS hotkey regression tests remain green.

## TDD plan
RED: fake-clock event sequences for threshold boundaries, chord before/after hold, repeat, both controls, missing release and cancellation. GREEN: X11 translation to shared policy. Run native press/release tests without requiring root or raw input-device access.

## Workflow and definition of done
- [ ] Create an isolated issue branch/worktree from updated main; keep one bounded change per PR.
- [ ] Record the failing behavioral test command/output before implementation, then the passing result; refactor without weakening assertions.
- [ ] Run `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked --workspace`, and `python3 scripts/check-repo.py`.
- [ ] Link tests and native evidence to each acceptance criterion; explicitly leave untested criteria open.
- [ ] Use synthetic data only; no credentials, personal paths, hostnames, user audio or transcripts in Git/issues/evidence.
- [ ] Push the issue branch, open a linked PR and remove its temporary worktree after preserving committed work.
