## Outcome
Replace the non-macOS entry-point rejection with capability-gated Linux orchestration while retaining native types inside platform adapters.

## Acceptance criteria
- [ ] Record the implementation target: distro/version, CPU architecture, desktop/version, X11 or Wayland, audio service and available microphone; use sanitized evidence.
- [ ] Detect X11, Wayland, headless and missing session bus using injectable probes; environment variables alone do not prove a capability works.
- [ ] Represent audio, shortcut, insertion, clipboard and indicator availability independently; failed capability probes never report ready.
- [ ] Desktop startup and manual dictation use shared lifecycle/cancellation contracts; unsupported headless startup fails clearly without hanging.
- [ ] Document the selected native dependencies and licensing; macOS contracts remain covered.

## TDD plan
RED: table-driven capability tests for missing/invalid display, portal denial, bus disconnect and partial support. GREEN: minimal Linux adapters and entry routing. Refactor after lifecycle and macOS regressions pass.

## Workflow and definition of done
- [ ] Create an isolated issue branch/worktree from updated main; keep one bounded change per PR.
- [ ] Record the failing behavioral test command/output before implementation, then the passing result; refactor without weakening assertions.
- [ ] Run `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked --workspace`, and `python3 scripts/check-repo.py`.
- [ ] Link tests and native evidence to each acceptance criterion; explicitly leave untested criteria open.
- [ ] Use synthetic data only; no credentials, personal paths, hostnames, user audio or transcripts in Git/issues/evidence.
- [ ] Push the issue branch, open a linked PR and remove its temporary worktree after preserving committed work.
