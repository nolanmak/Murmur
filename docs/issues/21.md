## Outcome
Provide the Murmur desktop indicator and manual dictation controls on Linux.

## Acceptance criteria
- [ ] Visible states cover idle, recording, processing, cancellation, delivery outcome, review/copy and actionable errors.
- [ ] Manual start, stop and cancel work without a registered hotkey; recording starts visually only when capture is ready.
- [ ] Indicator does not steal the insertion target; resizing, scaling and multiple monitors do not clip text or lose rounded corners.
- [ ] A supported launch/control surface remains accessible when the desktop has no tray support.
- [ ] Screenshots with synthetic text cover every state at supported scale factors; a debug run completes repeated sessions without a crash.

## TDD plan
RED: shared state transitions and renderer/layout tests for long errors and scale changes. GREEN: native Linux shell. Native screenshots plus real manual and shortcut flows verify focus and lifecycle; preview-only screenshots do not satisfy recording acceptance.

## Workflow and definition of done
- [ ] Create an isolated issue branch/worktree from updated main; keep one bounded change per PR.
- [ ] Record the failing behavioral test command/output before implementation, then the passing result; refactor without weakening assertions.
- [ ] Run `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked --workspace`, and `python3 scripts/check-repo.py`.
- [ ] Link tests and native evidence to each acceptance criterion; explicitly leave untested criteria open.
- [ ] Use synthetic data only; no credentials, personal paths, hostnames, user audio or transcripts in Git/issues/evidence.
- [ ] Push the issue branch, open a linked PR and remove its temporary worktree after preserving committed work.
