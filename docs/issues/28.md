## Problem
A successful transcript can end with a generic Copy Last Transcript instruction. Confirmed terminal failures are the multi-item clipboard guard in paste_text; other paths reuse similar copy instructions for missing focus or failed clipboard preservation. The UI should distinguish transcription success from delivery failure and give a recoverable action.

## Scope
Introduce structured local delivery outcomes and map them to concise indicator/menu messages. Preserve the transcript in memory for explicit recovery. This issue does not implement remote transport or bypass clipboard protections. Related: #6, #7, #10.

## Acceptance criteria
- [ ] Distinguish missing initial target, changed target, secure/unsupported target, unsupported clipboard, clipboard ownership loss, failed write and unverified paste dispatch in internal outcomes.
- [ ] Unsupported clipboard message explains that transcription succeeded but insertion was blocked; the menu exposes an explicit copy action and explains that it replaces the clipboard.
- [ ] Manual copy checks native write success and reports failures honestly, including possible clipboard modification after a failed destructive write. Copying must not claim the transcript was inserted into the terminal. Coordinate explicit copy with #27 recovery state so an old pending restore cannot overwrite the new copy.
- [ ] Focus-change recovery never automatically pastes into the newly focused application. Retry, if provided, requires an explicit action and fresh safe target validation.
- [ ] Delivery notices auto-expire using the existing NOTICE_MS timing (currently 3500 ms), while the menu retains the specific recovery action. Test this with a fake clock. Keep permission warnings separate: the persistent yellow Warning state is driven by keyboard permissions, not clipboard failure; do not dismiss a real permission problem to hide a delivery notice. The transcript remains recoverable until its documented replacement/clear boundary.
- [ ] Each new attempt clears stale delivery status; cancel, empty transcript and subsequent successful Notes/terminal dictation produce correct state transitions.
- [ ] Diagnostics contain only bounded reason codes/metadata, not transcript, clipboard data, window titles or personal paths.
- [ ] After #27, ordinary supported two-item clipboards must succeed, not reproduce the old rejection. Exercise failure recovery with a deterministic unsupported fixture (such as exceeding the documented item/byte bound): display the specific cause, explicitly copy, manually paste into a disposable terminal input, and verify actual content without Enter. Notes/browser regression checks pass.
