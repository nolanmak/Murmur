## Outcome
Establish a supported Wayland path before promising hold-Control or automatic paste. Evaluate GlobalShortcuts and authorized RemoteDesktop/Clipboard portal capabilities on the selected desktop.

## Acceptance criteria
- [ ] Publish a versioned GNOME/KDE target matrix with tested, unsupported and untested statuses; test the chosen primary target natively.
- [ ] Verify whether modifier-only hold registration and activation/deactivation are available; if unavailable, expose a supported configurable shortcut and manual start/stop.
- [ ] Permission denial, absent portal/backend and session revocation produce useful recovery without privilege escalation or silent X11 assumptions.
- [ ] Demonstrate text delivery into native Wayland and XWayland applications separately, or explicitly document review/copy-only mode for unsupported combinations.
- [ ] Do not inject into an unverified target automatically; document focus/security limits and user confirmation policy.
- [ ] No root, unrestricted evdev/uinput access or disabling desktop security is required for the default supported path.

## TDD plan
RED: fake portal tests for unsupported versions, denial, delayed activation, revocation and delivery failure. GREEN: smallest verified portal adapter. A native feasibility report is a checkpoint; do not close this implementation issue with a report alone or hide missing automatic insertion behind a success message.

## Workflow and definition of done
- [ ] Create an isolated issue branch/worktree from updated main; keep one bounded change per PR.
- [ ] Record the failing behavioral test command/output before implementation, then the passing result; refactor without weakening assertions.
- [ ] Run `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked --workspace`, and `python3 scripts/check-repo.py`.
- [ ] Link tests and native evidence to each acceptance criterion; explicitly leave untested criteria open.
- [ ] Use synthetic data only; no credentials, personal paths, hostnames, user audio or transcripts in Git/issues/evidence.
- [ ] Push the issue branch, open a linked PR and remove its temporary worktree after preserving committed work.
