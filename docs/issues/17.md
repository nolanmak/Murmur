## Outcome
Connect a real Linux microphone backend to the existing mono 16 kHz Deepgram Nova-3 stream; choose and document PipeWire/PulseAudio compatibility after target discovery.

## Acceptance criteria
- [ ] Enumerate/select microphone sources and handle absent device, denied access, unplug and default-device changes with visible errors.
- [ ] Use bounded buffers, correct channel conversion/resampling and existing duration/watchdog limits; never silently record desktop output.
- [ ] Release finalizes the provider stream and includes final words exactly once; cancel discards late results and closes microphone/network resources.
- [ ] Manual start/stop produces a transcript from a real microphone with a locally supplied key on the declared target.
- [ ] No real credentials, user recordings or transcripts enter CI, logs, fixtures or commits.

## TDD plan
RED: synthetic PCM conversion fixtures, overflow/no-frame tests and a fake WebSocket server for finalization, network failure and cancel races. GREEN: backend integration. Native opt-in mic test verifies actual capture; mocked success is insufficient.

## Workflow and definition of done
- [ ] Create an isolated issue branch/worktree from updated main; keep one bounded change per PR.
- [ ] Record the failing behavioral test command/output before implementation, then the passing result; refactor without weakening assertions.
- [ ] Run `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked --workspace`, and `python3 scripts/check-repo.py`.
- [ ] Link tests and native evidence to each acceptance criterion; explicitly leave untested criteria open.
- [ ] Use synthetic data only; no credentials, personal paths, hostnames, user audio or transcripts in Git/issues/evidence.
- [ ] Push the issue branch, open a linked PR and remove its temporary worktree after preserving committed work.
