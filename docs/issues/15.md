## Outcome
Deliver native Linux dictation using the existing Deepgram pipeline. This is a planning epic, not a claim that Linux already works. RustDesk integration remains separate in #13.

## Acceptance criteria
- [ ] All child issues have linked test evidence and their native acceptance gates pass before this epic closes.
- [ ] Publish an explicit distro, architecture, desktop, session and audio support matrix; distinguish verified support, experimental support and unsupported environments.
- [ ] On a supported desktop, hold the configured shortcut, see recording feedback, speak, release, and receive text in the intended input; manual start/stop works without a shortcut.
- [ ] Headless machines receive actionable diagnostics; installing on a server does not create a microphone or a graphical input target.
- [ ] Keep macOS behavior working and document supported Wayland fallbacks without claiming universal input support.

## TDD plan
First add failing end-to-end acceptance scenarios for manual dictation, shortcut dictation, missing audio and unsupported sessions. Complete child red/green cycles, then demonstrate the release matrix.

## Workflow and definition of done
- [ ] Create an isolated issue branch/worktree from updated main; keep one bounded change per PR.
- [ ] Record the failing behavioral test command/output before implementation, then the passing result; refactor without weakening assertions.
- [ ] Run `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked --workspace`, and `python3 scripts/check-repo.py`.
- [ ] Link tests and native evidence to each acceptance criterion; explicitly leave untested criteria open.
- [ ] Use synthetic data only; no credentials, personal paths, hostnames, user audio or transcripts in Git/issues/evidence.
- [ ] Push the issue branch, open a linked PR and remove its temporary worktree after preserving committed work.
