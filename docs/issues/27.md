## Confirmed diagnosis
Runtime diagnostics show successful transcription, a recognized editable terminal target with paste=true, then `Use Copy Last Transcript (clipboard has multiple items)`. Notes succeeds with paste=false. In src/platform/macos.rs, paste_text rejects any pasteboard containing more than one item before dispatching Cmd+V. Notes can use AXSelectedText and bypass this path. This is a clipboard-dependent insertion failure, not a demonstrated transcription or hotkey failure. Which app originally populated the clipboard is unknown and irrelevant to reproduction.

The local path flattens clipboard formats and restores after a fixed one-second timer. The existing MacClipboard adapter also rejects multiple items; simply routing through it will not resolve the bug.

Implement item-aware preservation for local macOS clipboard insertion. Keep item boundaries, order and materialized types/data. Extract the local clipboard transaction behind an injectable interface as needed. Do not loosen focus/security checks or change RustDesk's explicit review policy. - [ ] Native matrix covers empty, single text, two text items, mixed supported formats and concurrent copy against a disposable terminal input; Notes and browser insertion still work. Keep untested terminal variants explicitly pending.
