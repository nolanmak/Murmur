## Confirmed diagnosis
Runtime diagnostics show successful transcription, a recognized editable terminal target with paste=true, then `Use Copy Last Transcript (clipboard has multiple items)`. Notes succeeds with paste=false. In src/platform/macos.rs, paste_text rejects any pasteboard containing more than one item before dispatching Cmd+V. Notes can use AXSelectedText and bypass this path. This is a clipboard-dependent insertion failure, not a demonstrated transcription or hotkey failure. Which app originally populated the clipboard is unknown and irrelevant to reproduction.

For the accepted zero/one-item case, the local path stores board-level formats and restores after a fixed one-second timer; it never reaches that code for multiple items. Extending it by removing the guard alone would lose item boundaries. The existing MacClipboard adapter also rejects multiple items; simply routing through it will not resolve the bug.

## Scope
Implement item-aware preservation for local macOS clipboard insertion. Keep item boundaries, order and materialized types/data. Extract the local clipboard transaction behind an injectable interface as needed. Do not loosen focus/security checks or change RustDesk's explicit review policy. Coordinate shared adapter changes with #13; Linux insertion remains #19. Related: #6.

## Acceptance criteria
- [ ] A supported clipboard containing two or more materialized items no longer blocks dictation into Ghostty and Apple Terminal; Unicode text arrives exactly once. These two apps are mandatory native gates. Record iTerm2 as tested or explicitly unverified; do not claim it is verified when unavailable.
- [ ] Preserve each supported item's order, type identifiers and bytes, including multiple representations per item; restoring must not flatten items into a single item.
- [ ] Check snapshot consistency and revisions immediately before every destructive write/restoration. A detected revision mismatch must abort without further writes. Cover injected ownership changes at every observable boundary. Document the remaining check-to-write race: NSPasteboard provides no atomic compare-and-swap, so do not claim absolute overwrite prevention.
- [ ] Define and test per-item/count/total-size bounds and behavior for unavailable/lazy/file-promise data before changing clipboard contents. Unsupported snapshots retain the transcript and clipboard with an explicit reason.
- [ ] Check native write results and handle partial write failure with recoverable state; never report success solely because shortcut creation succeeded.
- [ ] Remove unconditional one-second restoration from the unacknowledged paste path. Keep the transcript available for delayed consumption and provide explicit Restore previous clipboard after the user has pasted; restoring checks the owned revision. Automatic restoration requires an actual supported consumption acknowledgement, not a timer. Test a reader delayed beyond one second. Define a bounded recovery lifecycle for consecutive dictations, explicit copy, cancellation and quit: never silently replace a pending snapshot or restore an older attempt over newer text; explain when user action is needed to resolve it.
- [ ] Retain existing PID, retained AX element equality, editable/secure and control-character checks. Revalidate as late as possible before dispatch and block detectable app/window/element changes, cancellation and stale results. Test detectable terminal-tab changes, and document cases where a terminal reuses the same AX element rather than promising universal tab detection. Never synthesize Enter, interpret transcript text as code, or automatically submit a command.
- [ ] Native matrix covers empty, single text, two text items, mixed supported formats and concurrent copy against a disposable terminal input; Notes and browser insertion still work. Keep untested terminal variants explicitly pending.
