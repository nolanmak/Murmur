# Local macOS paste and clipboard recovery

Murmur uses a temporary clipboard item followed by Command-V for recognized macOS text inputs in any app, including Messages, WhatsApp, Slack, Discord, Notes, browsers and terminals. It does not rely on direct Accessibility text writes: some editors acknowledge those writes without changing their contents. Murmur requests Accessibility exposure from the focused app before reading the input, including Electron apps. Dispatching the paste shortcut cannot prove the target consumed the text, so the app reports **Paste sent · verify text in target**. It never sends Enter or runs the transcript as a command.

Supported inputs expose AXTextField, AXTextArea or AXComboBox. Known terminal surfaces also support their group/scroll-area roles. Password fields remain blocked. Apps that expose only an opaque custom canvas, disable Accessibility, or ignore synthetic paste are not guaranteed; Murmur does not blindly paste into an arbitrary window. RustDesk continues to use its separate remote clipboard workflow.

Before a local paste, Murmur materializes supported clipboard items in order, retaining each type identifier and its bytes. The limits are 32 items, 32 formats per item, 8 MiB per item and 16 MiB total. Unavailable data and promised formats are unsupported. In those cases, transcription remains available through **Copy Last Transcript (replaces clipboard)**, and the clipboard is left alone. The explicit copy action can replace clipboard contents; use it only after considering what is currently copied.

After a successful paste request, another dictation can replace the temporary transcript without requiring Restore. Murmur retains the original clipboard snapshot across consecutive pastes. **Restore clipboard from local paste…** remains optional. Wait for the previous text to appear before another dictation or restoration; dispatch cannot confirm consumption by a slow reader. A newer external copy becomes the recovery snapshot for the next paste. Failed writes or dispatches still require recovery. Quitting loses the in-memory snapshot and leaves the current clipboard unchanged.

**Copy Last Transcript** stays available until a new recording attempt or Murmur quits. Starting an attempt clears it even if preflight rejects the target. Clipboard recovery is maintained separately from this transcript.

Clipboard writes on macOS have no atomic compare-and-swap operation. Murmur checks the change count immediately before destructive operations and aborts on detected ownership changes. A change between that check and a native write remains possible. Terminal tabs that reuse the same Accessibility element may also be indistinguishable; Murmur revalidates the original process and retained element just before insertion. Always inspect the intended target before speaking and verify the inserted text before pressing Enter.

For debug builds only, launch `Murmur.app/Contents/MacOS/murmur run --local-fixture` to add **Insert synthetic test phrase** to the menu. It uses the real local focus and paste path with synthetic text, without microphone or Deepgram. Use a disposable terminal input and inspect actual text. Native automated clipboard tests use uniquely named pasteboards and do not read the user's general clipboard.

The debug menu also provides **Capture synthetic test target** and **Insert at captured synthetic target**. Capture a disposable terminal input, switch tabs or windows, then try insertion. A detectable target change must report a changed target without altering the clipboard or the newly focused input. The captured target is used once. A terminal that reuses the same Accessibility element and window may still be indistinguishable, as described above.

For controller-state checks, the same debug menu provides **Simulate synthetic dictation result**, **Simulate empty dictation result**, and **Simulate duplicate dictation result**. They use the normal preflight and completion route without opening a microphone or contacting Deepgram. Use a disposable text input. A duplicate result must not insert twice or replace the first result's status; an empty result must return to Idle so the next synthetic attempt can start.
